# carts/: sample games (and the user's projects)

The studio's workspace is the repo root, so everything the user makes also lands in `carts/<name>/`. Treat the folders as the user's data: don't rewrite, rename or "clean up" them unless asked.
A game is a **framework cart** (`game.lua`, `entities/`, `scenes/` (code and `<name>.layout.lua` layouts), `rooms/`, `lib/`, `sprites/ tilesets/ sfx/ music/ instruments/ sounds/`, `meta/info.json` for the game list) or a **raw Lua cart** (`main.lua` only, drawn at the runtime's own size). Details: `engine/AGENTS.md`.

| Cart | What |
| --- | --- |
| `breakout` | The reference framework game (Dot, 320x240): `entities/` paddle, ball, brick; `scenes/` title, play, over; `lib/` shared state and backdrop; sprites, a tileset, six sound effects, two songs. The first thing to read to learn the API; the best manual test of the sound editors |
| `void-swarm` | A space Survivors game (Dot): 10 pilots, 10 auto-firing weapons, 24 enemy types + 10 bosses, 10 sectors, permanent ship/weapon upgrades, 11 songs. **The large sample of the entity API.** `entities/` the ship, `enemies/` (24 files: each kind's numbers and `think()`; most just inherit "walk at the player"), `bosses/` (10, built on `entities/boss.lua`), `bullets/`, `weapons/`, pickup, fx, strike; `scenes/` title, hub, pilots, ship, weapons, stages, **play** (the director: spawner, hazards, boss, level-up and pause via `gs.pause`), results, audit; `lib/` data (pilots, weapons, sectors), run (the state of a run and shared combat helpers), save, weapons, targets, audio, ui, menu, controls, bot, debug. Art follows the size guide: pilots 24x24, three-quarters facing right, 8 frames (0-1 idle, 2-7 walk; the menus show the walk), the five big enemies 32x32 with 4-frame stomps for the rockling and golem, the rest 16x16, bosses 48x48, shots and pickups 8x8; hit circles are about 0.6 of the sprite (player 7). Entity budget: enemies 100(+20), bullets 100, pickups 120, shots 60, fx 50 (all well under Dot's 512). Assets come from `scripts/make-void-swarm.mjs` (art in `scripts/void-swarm/*.mjs`; it never touches code or `meta/info.json`). Test with the bot: `GS_BOT=1 GS_FF=20 GS_STAGE=3 GS_PILOT=2 GS_UPG=5 build/gs carts/void-swarm` (also `GS_T0` start second, `GS_SEED`, `GS_BOT_SECS`), `GS_TEXTAUDIT=1` (every screen; reports cut-off text), `GS_SCREEN=hub\|pilots\|ship\|weapons\|stages\|play\|levelup\|pause\|results` for screenshots, menus by `GS_BOT_LUA=tests/keys-bot.lua GS_KEYS=...`; all in `lib/debug.lua`. Saves are one table (`gs.save` key `progress`); the first version's text save is converted once. Measured on a desktop: about 0.3 ms a step in a busy sector, 1.3x the hand-tuned table version it replaced |
| `panel-pop` | A panel-swapping puzzler (Endless, Time Attack, Vs CPU against eight rivals, Stage Clear, Puzzle). **The sample of scene layouts**: every screen is `scenes/<name>.lua` with `<name>.layout.lua` (a `sky` tile layer from `ts_sky`, window panels from `ts_ui`, texts in the sprite fonts `spr_font` / `_r` / `_w` / `_y`, pictures); `versus.layout.lua` runs `play`'s code (`code = "play"`); the end banner and pause menu are `screen = true` items. Boards are tables of cells, not entities: rules `lib/pl.lua`, CPU `lib/plai.lua`, a game of any mode `lib/game.lua`, drawing `lib/board.lua`, shared helpers `lib/ui.lua` (fonts, sky, menu rows, sound), `lib/save.lua`, `lib/data.lua` (rivals, difficulties, stages), `lib/puzzles.lua`, generated `lib/art.lua`. Self-test: `GS_SELFTEST=1 build/gs carts/panel-pop` prints `PANEL POP TEST PASS` (part of `tests/run.sh`); shortcuts `GS_MODE`, `GS_BOT`, `GS_SCREEN` in `lib/debug.lua`. Generators: `scripts/make-panel-pop.mjs` (art and sound) and `make-panel-pop-art.mjs` (box art) |
| `derelict` | A sci-fi metroidvania, so far **one test room for the controls** (`scenes/station.lua` + `station.layout.lua`, 60x30 tiles). D-pad runs, Up aims up (and uses a terminal), Down crouches or aims down in the air, B jumps (hold for higher; coyote time and a jump buffer), Down+B drops through a thin floor, Y shoots (held: auto-fire), and five upgrade capsules add A dash, double jump, wall jump, charge shot (hold Y) and missiles (X fires one). Four-way aiming only. The hero moves itself against the `solid` tile layer through `lib/tiles.lua` (tiles 0-15 walls, 16-23 thin floors) and keeps its speed in `speed_x`/`speed_y`, not `vx`/`vy`; what the player has found is `lib/state.lua`. Art, the room and `lib/art.lua` come from `scripts/make-derelict.mjs` (art in `scripts/derelict/art.mjs`, the room in `level.mjs`); the sound effects are Void Swarm's for now |
| `buttontest`, `padsetup` | Small framework carts for checking controller buttons on a device (they call the runtime's `gs.btn`, `gs.pad_last`, `gs.pad_set` directly); Pad setup also records the HOTKEY |

`tests/run.sh` runs `breakout`, `void-swarm`, `panel-pop` and `derelict` headless and requires no errors or warnings, so keep them loading.
