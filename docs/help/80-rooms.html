Big levels: layouts, tiles and the camera

The Glow43 screen is 320x240 pixels. A level can be much bigger, and the camera decides which part of it you see. A level is a scene's layout made bigger than the screen: how big it is, its background, its tile layers, and which entities start where.

A big layout

Open a scene's Layout, and on the Details tab on its left pick Bigger: it scrolls and type a width and height. The dashed box in the layout is one screen. Select picks things up and moves them, Tiles paints the chosen layer (Shift-click fills, right-click picks a tile up, Alt-click erases), Entities places the entity chosen on the right, and Paths draws routes. Saving writes plain data you can read (and write) yourself; Edit as text on the Details tab shows it. Entities are { name, x, y } (an optional fourth value is a table of values to set; name = makes it self.<name> in the scene's code):

-- The scene's layout, built when it starts. Named things are fields of its code: self.<name>.
return {
  width = 640, height = 480,           -- bigger than the screen: the camera will scroll
  background = "#14234f",
  entities = {
    { "walker", 320, 240, {}, name = "walker" },
    { "tree", 100, 100 }, { "tree", 520, 90 }, { "tree", 300, 380 },
    { "tree", 80, 400 },  { "tree", 560, 420 }, { "tree", 450, 250, { size = 14 } },
  },
}

Paths

A path is a list of points in the level, for a guard's patrol or a platform's route. Draw it in the layout editor, or write it in the layout:

paths = {
  patrol = { { 40, 40 }, { 280, 40 }, { 280, 200 }, loop = true },
},

An entity walks it with self:follow_path("patrol", 60) (60 pixels a second). A path that does not loop ends by calling the entity's on_path_end; self:stop_path() stops early. gs.path("patrol") gives the points if you want to use them yourself.

The things in it

local Tree = gs.entity{
  size = 10,
  depth = 5,
}

function Tree:draw()
  gs.draw.rect(self.x - 2, self.y, 4, self.size, "#9a5324")
  gs.draw.circle(self.x, self.y - 2, self.size, "#2f8a3f")
end

return Tree
local Walker = gs.entity{
  speed = 100,
}

function Walker:update(dt)
  local dx, dy = gs.input.dir()
  self.x = gs.clamp(self.x + dx * self.speed * dt, 8, 632)
  self.y = gs.clamp(self.y + dy * self.speed * dt, 8, 472)
end

function Walker:draw()
  gs.draw.circle(self.x, self.y, 7, "#ffa38c")
end

return Walker

The camera

A big layout already tells the camera the size of the level, so it never shows the empty space outside. All that is left is whom to follow. smooth is how lazily the camera catches up (0 is stiff, 0.1 a little soft, 0.3 floaty). gs.camera:shake(amount, seconds) is for hits and explosions; gs.camera:set(x, y) moves it directly (for a cutscene).

local Main = gs.scene{}

function Main:enter()
  gs.camera:follow(self.walker, { smooth = 0.1 })   -- the walker the layout placed and named
end

function Main:draw_ui()
  gs.draw.text("THE ARENA IS 640x480", 8, 6, "#ffffff", 1, { shadow = true })
end

return Main

Things the camera cares about: anything drawn in draw of an entity is in world coordinates, so it scrolls. Anything drawn in a scene's draw_ui (and an entity with screen = true) is in screen coordinates and stays put, like a score.

Zoom. gs.camera.zoom = 2 shows the world twice as big (a quarter of it fits on the screen); the camera still keeps to the level's edges. Whole numbers keep pixel art crisp. draw_ui is never zoomed, so the score stays the same size. Going to another scene puts the zoom back to 1.

Many levels, one set of rules

Ten levels are ten layouts. Two ways to play them, both plain code:

  • A scene per level. Make level1, level2, ... under Scenes, and on each layout's Details tab set Runs the code of to one scene (say play). Every level then runs the same rules, and gs.goto_scene("level" .. (n + 1)) moves on.
  • Build a layout into the running scene with gs.load_layout(name): for a level picked from code, or one made of pieces. Its things, tiles and paths are added to what is there, and its named things become fields of the running scene.
function Play:enter(n)
  gs.load_layout("levels.level" .. n)   -- scenes/levels/level3.layout.lua when n is 3
end

Older games keep levels in rooms/, the earlier home of the same data. They still load (gs.load_room is the older name of gs.load_layout), and Make it a scene layout on a room's Details tab moves one to Scenes.

Tile layers

Real levels are made of tiles drawn in the tileset editor: a picture sheet where each tile is 8, 16 or 32 pixels square. A layer is a grid of tile numbers (counting from 0, left to right then down; -1 is empty). Paint them with the layout editor's Tiles tool, or add them by hand with gs.add_layer:

-- in scenes/main.layout.lua
layers = {
  { tileset = "ground", depth = 100, data = {
      { 0, 0, 1, 0 },
      { 0, 1, 1, 0 },
    } },
  -- a far-away layer that moves at half the camera's speed and repeats sideways
  { tileset = "clouds", depth = 90, scroll_x = 0.5, wrap_x = true, data = { { 0, 1, 2, 1 } } },
},

A layer is drawn from one picture that the engine builds once, so a big map costs almost nothing per frame. Ask a layer what is at a spot with gs.tile_at(layer, x, y) (for walls and floors), and change it with gs.set_tile. Glow43 allows four tile layers in a level. Names go with the files: "ground" is tilesets/ground.json.
