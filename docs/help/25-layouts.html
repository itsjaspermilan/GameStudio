Layouts: placing things in a scene

A scene has two halves, and its tab above the editor has both: click Layout or Code in it to switch.

  • Layout: what is placed where. Texts, pictures, entities, tile layers and paths, put in by dragging. It is saved as scenes/title.layout.lua.
  • Code: what the scene does: enter, update, draw_ui. It is scenes/title.lua.

When the scene starts, its layout is built first, then enter runs. Either half can be missing: a menu may be all layout with a few lines of code, and a scene that makes everything in code needs no layout.

A selected picture, text or panel, and the tile layer you paint on, have a Look: glow adds light to what is behind (a light shaft, fire), shadow darkens it (shade, night), and strength makes it see-through below 100%. The editor shows the look as the game will.

Which half does it go in?

If you can point at it when the scene starts, it goes in the Layout. If it changes, decides or comes and goes, it is Code.

A scene can be all Layout (a credits screen), all Code (a scene that builds a random level), or anything between. Breakout (on the start screen under Examples) is a good one to read: its play scene's layout holds the paddle, the ball, 48 bricks and the score bar, and its code is a dozen short lines.

Names connect the two

Give something in the layout a name (in the Selected panel) and the code has it as a field: a text named prompt is self.prompt, a picture named logo is self.logo. Texts and pictures get a name as soon as you place them; an entity gets one only if you give it one, so forty enemies don't make forty names. The layout editor shows each name as self.name above the thing.

The list on the left of the layout, In this layout, is the map of the scene: everything with a name, as the code calls it, and a click selects it. Typing self. in the scene's code lists the names, hovering one shows what it is, and a typo like self.promtp gets a warning. Renaming something in the layout renames it in the code too, when you save the layout.

A title screen

This layout has a big title and a blinking prompt. You would normally place them with the Text tool; this is what the editor writes:

return {
  width = 256, height = 192,
  background = "#14234f",
  entities = {
  },
  texts = {
    { "SKY HOP", 128, 56, name = "title", color = 15, size = 4, align = "center" },
    { "PRESS A", 128, 144, name = "prompt", color = 3, align = "center" },
  },
}

Panels and bars are made of tiles, like everything else on a pixel console: with the Panels tool, pick the top-left tile of a 3 × 3 block in a tileset and drag. The corners stay as drawn and the edges and middle repeat to fill the size; one tile high, a panel is a bar made of the block's top row. A text can use a built-in font in any palette colour: round, square or bold letters, each small (8 pixels high, for scores and labels) or tall (12 high, for talking and menus), with a shadow if you like, the way GBA games drew their words. Or it can use a font of your own: a sprite whose frames are the letters, from the space on in ASCII order.

The code only says what moves. A text has text, x, y, color, size and visible; a picture has sprite, frame and its scale in sx and sy. Both are entities, so tween works on them too.

local Title = gs.scene{}

function Title:enter()
  self.top = self.title.y
end

function Title:update(dt)
  self.title.y = self.top + math.sin(gs.time() * 3) * 4  -- the title bobs
  self.prompt.visible = gs.time() % 1 < 0.6             -- the prompt blinks
  if gs.input.pressed("a") then
    self.prompt.text = "GO!"
  end
end

return Title
return gs.game{
  title = "Sky Hop",
  console = "glow43",
  start = "scenes.title",
}

Press Run and the game shows in the Play panel. Move a text in the layout, save, and the running scene starts again with the new layout.

Many levels, one set of rules

Each level can be a scene with its own layout. They don't each need their own code: in a level's layout, Code (on the right) picks another scene's code to run. With level1 to level10 all running level's code, that code can count on every level having the names it uses, say self.door. Renaming door in one level renames it in the others too.

-- scenes/level1.layout.lua
return {
  code = "level",
  entities = { { "player", 32, 160, {}, name = "player" }, { "door", 224, 160, {}, name = "door" } },
}
Rooms (rooms/, Big levels) are the older way to do this: the same data, built by gs.load_room from code. They still work.
