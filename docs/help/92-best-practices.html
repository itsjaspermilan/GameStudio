Best practices

Small habits that make a game still easy to change after a month.

Layout

  • One kind of thing, one file. entities/grub.lua holds everything about grubs. When something is wrong with grubs you know where to look.
  • Scenes decide, entities act. A scene spawns, counts and ends things. An entity moves itself and reacts to what it touches. Rules that belong to nobody (score, waves, win and lose) go in the scene.
  • Shared state in lib/. A small table in lib/state.lua, not global variables. A require at the top of a file shows what the file depends on.
  • Folders for families. entities/enemies/grub.lua is spawned as gs.spawn("enemies.grub").
  • Data that designers change is data. Numbers at the top of the entity table (hp = 3, speed = 40), not buried in the middle of a function. Rooms, wave lists and item tables are plain Lua tables in their own file.

Name things for what they are

Tags are nouns (enemy, pickup), methods are verbs (hurt, collect), and booleans read as questions (grounded, invulnerable). Tags are how entities talk to each other, so spend a minute to choose them.

Reuse with inheritance

gs.entity(Parent, { ... }) builds a new kind of thing on an existing one. The child has all the parent's methods and starting values, and the table you give replaces the ones that differ. Override a method by defining it again; call the parent's version with Parent.method(self, ...).

local Enemy = gs.entity{
  tags = { "enemy" },
  hp = 3,
  speed = 40,
  size = 6,
}

function Enemy:update(dt)
  self.x = self.x + self.speed * dt
  if self.x > 340 then self.x = -20 end
end

function Enemy:hurt(amount)
  self.hp = self.hp - amount
  if self.hp <= 0 then self:destroy() end
end

function Enemy:draw()
  gs.draw.circle(self.x, self.y, self.size, "#6ccf4f")
end

return Enemy
local Enemy = require "entities.enemy"

-- A boss is an enemy with more of everything, and a flash when it is hurt.
local Boss = gs.entity(Enemy, {
  hp = 30,
  speed = 15,
  size = 16,
})

function Boss:hurt(amount)
  Enemy.hurt(self, amount)                 -- the enemy's version does the counting
  self:tween({ alpha = 0.3 }, 0.05)        -- then ours adds a flash
  self:after(0.1, function() self.alpha = 1 end)
end

return Boss
local Main = gs.scene{}

function Main:enter()
  gs.spawn("enemy", -20, 60)
  gs.spawn("boss", -40, 140)
  self:hit_something()
end

function Main:hit_something()
  -- both are "enemy"-tagged, so code that looks for enemies finds the boss too
  gs.each("enemy", function(e) e:hurt(1) end)
end

function Main:update(dt)
  if gs.count("enemy") < 2 then
    gs.spawn("enemy", -20, gs.random(20, 220))
  end
end

function Main:draw_ui()
  gs.draw.text("ENEMIES: " .. gs.count("enemy"), 8, 6, "#ffffff")
end

return Main

Prefer a shallow family (an enemy, a few kinds of enemy) to a deep one. When two things only share a little, give them a shared function in lib/ instead of a parent.

Sparks, dust and smoke

For little effects use gs.burst(x, y, { count = 10, color = "#ffd08a", gravity = 160 }) instead of spawning entities: particles fly, fall and fade by themselves, never collide, and do not count toward the 512 entities. The console caps them (300 on Dot). Breakout's bricks use it.

While you work

  • Keep the game running. Change a file and save: the game reloads that code and keeps its state. It is the fastest way to tune jumps, speeds and timings. Starting values in an entity's table apply to new entities; go to the scene again (gs.goto_scene) to see them on everything.
  • Listen to the editor. Red underlines are real mistakes; amber ones are worth a look. The Handheld tab is there so a problem is a number you can see, not a surprise on the device.
  • Use git. The game is plain files, so commit when it works and experiment freely.
  • Small steps. Make the player move, then one enemy, then collisions. A game that runs after every step is easy to fix.

Test it without playing it

The runtime can play a game by itself for a while, which finds crashes you would meet on the third level. From the GameStudio folder in a terminal:

GS_BOT_LUA=tests/random-bot.lua GS_FF=20 GS_MAX_FRAMES=300 build/gs carts/mygame

The bot presses buttons at random, fast-forwarded twenty times, for 300 frames; any Lua error is printed. The tutorials on this page run the same way in the studio's own tests.
