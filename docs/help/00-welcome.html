Welcome to GameStudio

GameStudio makes small 2D games for a cheap handheld (an Anbernic RG35XX Pro running Knulli) and runs them on your computer while you work. You write the game in Lua, a small, friendly language. You draw the sprites and make the sound and music in editors built into this window.

The folder is the game

A game is just a folder, and it can be anywhere on your computer: New game asks where to put it, Open folder… opens one you already have, and the start screen lists the ones you opened lately. Everything you see in the list on the left is a file in it, so you can also use git, your own text editor, or move files around outside the studio. Show folder opens it in Finder.

Folder / fileWhat it holds
game.luaThe game's title, the console it is made for, and the first scene.
entities/Things in your game: the player, enemies, bullets. One Lua file for each kind of thing.
scenes/Screens: the title, the level, game over. Each has a Layout (title.layout.lua: what is placed where) and Code (title.lua: what happens).
rooms/The older form of level data (a scene's layout does the same now, see Layouts).
lib/Shared code and game state you load with require.
sprites/, tilesets/Pictures, drawn in the sprite editor.
sfx/, music/, instruments/, sounds/Sound effects and songs, made in the sound editors; imported WAV samples.
palette.jsonThe game's colour banks (Colours in the list).
meta/The title, description and box art the handheld's game list shows (Game info…). Not packed into the game.
.gamestudio/The studio's own notes about the game (open tabs, where you were), like a code editor's settings folder. Hidden, never packed, safe to delete.

Run it, change it, watch it change

Press Run (or Cmd/Ctrl+Enter). The game plays in the Play panel beside the code (click it, then use the arrow keys and Z / X; Settings can open games in a window of their own instead). While it runs, change a Lua file and save: the game picks up the new code without restarting and keeps its state, so you can tune a jump or an enemy while you play. If you make a mistake the game shows the error on screen and carries on when you fix it.

The keys: arrow keys move, Z is A, X is B, A is X, S is Y, Q and W are the shoulder buttons L and R, Enter is Start, right Shift is Select, E and R are L2 and R2, and Esc closes the game. On the handheld, HOTKEY + Start closes it, as in every other app.

Helpers in the editor

  • Completion. Type gs. and pick from the list. Inside quotes the list shows what your game has: gs.spawn(" lists your entities, gs.sfx(" your sound effects.
  • Hover. Rest the mouse on gs.draw.rect (or any name from the game) to see what it does.
  • Warnings. A red mark means a name does not exist (with a "did you mean"). Amber is worth a look.
  • Ctrl-click (Cmd-click on a Mac) a name like "enemy" in gs.spawn("enemy") to open its file. F12 jumps to where a name is defined, Shift+F12 lists everywhere it is used, F2 renames it everywhere.
  • Find in game (Ctrl/Cmd+Shift+F) searches every Lua file and can replace. Tidy (Shift+Alt+F) puts the indentation right and wraps long comments at 100 characters; Go to… lists the functions in the file.
  • The Inspector tab looks inside the running game: pause it, step one frame, slow it down, see each kind of thing with what it costs, and watch values.
  • The Handheld tab under the editor shows how your game compares with what the handheld can do: size, sprite sizes, and, while the game runs, how many things are alive, the RAM in use and about how long a frame would take on the Brick.

A finished example

Open Breakout (it is also under Examples on the start screen). The studio makes a copy in a folder you pick, so you can change it freely. Press Run, then look around: every screen is a scene whose Layout holds what you see (the wall of bricks, the score bar, the words) and whose Code is a few lines. Three entities (paddle, ball, brick) do the rest.
