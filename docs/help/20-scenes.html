Scenes, menus and saving

A game is a chain of scenes: title, play, results. Each is a file in scenes/. This page builds a tiny three-scene game, "Button Masher": press A as often as you can for five seconds.

Moving between scenes

gs.goto_scene("scenes.play") ends the current scene at the end of the step and starts the other. Everything the old scene made (entities, timers) is cleared. Two options make it nicer:

  • { fade = 0.3 } fades the screen out and back in over 0.3 seconds.
  • Anything after the options is handed to the next scene's enter: gs.goto_scene("scenes.over", { fade = 0.3 }, score) arrives as function Over:enter(score).

The title screen

gs.ui.menu makes a list you move through with up and down and pick with A. Its update returns the number of the item that was picked, or nil. It rolls open line by line the first time it is drawn, and menu:close() rolls it away again (menu.closed is true once it is gone). Saved values come back with gs.save.get(key, default).

local Title = gs.scene{}

function Title:enter()
  self.menu = gs.ui.menu({ "PLAY", "RESET BEST SCORE" })
  self.best = gs.save.get("best", 0)
end

function Title:update(dt)
  local pick = self.menu:update()
  if pick == 1 then
    gs.goto_scene("scenes.play", { fade = 0.3 })
  elseif pick == 2 then
    gs.save.set("best", 0)
    self.best = 0
  end
end

function Title:draw_ui()
  gs.draw.text_centered("BUTTON MASHER", 50, "#ffd08a", 2)
  gs.draw.text_centered("BEST " .. self.best, 90, "#8a90a8")
  self.menu:draw(110, 140)
end

return Title

The game

Scenes are tables, so a scene can keep its own values in self. gs.draw.bar draws a bar that shows a value out of a maximum.

local Play = gs.scene{}

function Play:enter()
  self.score = 0
  self.time_left = 5
end

function Play:update(dt)
  if gs.input.pressed("a") then
    self.score = self.score + 1
  end
  self.time_left = self.time_left - dt
  if self.time_left <= 0 then
    gs.goto_scene("scenes.over", { fade = 0.3 }, self.score)    -- hand the score on
  end
end

function Play:draw_ui()
  gs.draw.text_centered("PRESS A!", 60, "#ffffff", 2)
  gs.draw.text_centered(tostring(self.score), 110, "#ffa38c", 4)
  gs.draw.bar(60, 200, 200, 10, self.time_left, 5, { color = "#6ccf4f" })
end

return Play

The results, and remembering a high score

gs.save.set keeps a value in the game's save file, so it is still there next time the game starts, on your computer and on the handheld. Values can be numbers, text, true/false, or tables of those. Keys use letters, digits and _. For several players or save files, gs.save.slot(2).set("best", 10) keeps a separate set.

local Over = gs.scene{}

function Over:enter(score)                  -- the value that play.lua handed on
  self.score = score
  self.new_best = score > gs.save.get("best", 0)
  if self.new_best then gs.save.set("best", score) end
end

function Over:update(dt)
  if gs.input.pressed("a") or gs.input.pressed("start") then
    gs.goto_scene("scenes.title", { fade = 0.3 })
  end
end

function Over:draw_ui()
  gs.draw.text_centered("TIME!", 60, "#ffd08a", 2)
  gs.draw.text_centered("SCORE " .. self.score, 110, "#ffffff", 2)
  if self.new_best then gs.draw.text_centered("NEW BEST!", 150, "#6ccf4f") end
  gs.draw.text_centered("PRESS A", 200, "#8a90a8")
end

return Over
return gs.game{
  title = "Button Masher",
  console = "glow43",
  start = "scenes.title",
}
Scenes are not entities. A scene runs once and owns the screen; entities are the many things inside it. A scene's update and draw_ui are the right place for rules that belong to no one entity: spawning waves, the score, ending the level.

Sharing state between scenes

Arguments are good for one value. For things that last the whole game (lives, collected items, the current level), keep a table in lib/state.lua and require it from anywhere, as in Your first game. Keep what must survive closing the game in gs.save.
