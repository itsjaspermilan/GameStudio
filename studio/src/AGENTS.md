# studio/src/: file map

Sizes are lines. Pure = no DOM, covered by a test in `../test/`.

| File | What |
| --- | --- |
| `main.js` (~700) | State, the tree, save/rename/delete, run/pack/push, creates every editor. Sections: log, code editor, the project's console, rendering, actions, consoles, changing a console, files, game info, resources (tree), sprites, tilesets, samples, **sound effects, music and instruments** (+ audio context, previews), toolbar, settings, boot |
| `project-core.js` pure | The project model: `GROUPS` (folders and how each opens), `scanProject` (file list to tree), `folderTree` / `movedName` (folders in the tree, for every group: a folder is part of the name, `ui/logo`; dragging to another folder is a rename), names and Lua module names, templates of new files, `newGameFiles` (the starter game), console in `game.lua` / `meta/info.json` |
| `mock-backend.js` | In-memory fake of the Rust commands for plain-browser development (demo projects, fake `render_audio`) |
| `audio-core.js` (~870) pure | Sound hub: sfx tracks/steps/ties, instruments + built-in set, key lock, `AudioDesc` (builds `gs render-audio` descriptions), tracker song model + note/kit ops, ranges, timing, drum beats, melody generator, starter songs, legacy converters |
| `lanes.js` | Canvas lanes (instrument box + piano roll / drum / drum kit strip): rows, snapping, resize, collapse, hover, playhead. Reports user actions through callbacks |
| `sfx-editor.js`, `music-editor.js` | The two lane editors (drag to stretch or move notes, overlapping notes on voices, per-lane key and volume, key lock, inspector strip, playback + playhead) |
| `instrument-panel.js` | Right-hand palette (drag instruments), colours, `CHANNEL_COLORS`, drag helpers |
| `instrument-editor.js` | Custom instrument editor (kind, wave drawing, ADSR, range, piano preview) |
| `lua-intel-core.js` pure | What the editor knows without a language server: reads `engine/api/gs.d.lua` (`parseApi`), the project index (tags, modules, `self` fields), cursor context, completion, hover, and the lint rules (unknown sprite/sound/entity/scene/tag names with "did you mean", missing `return`, tables allocated in `update`) |
| `lua-highlight.js` | The code editor's Lua colouring: a tokenizer of its own (keywords, the function being defined, calls, fields, `self`, `gs` and the standard library, class names, `---@` annotations) and one highlight style whose colours are `--hl-*` CSS variables (light and dark in `style.css`) |
| `lua-editor.js` | The CodeMirror extensions over it: completion (own first, then the server), hover, linter (own + server), ctrl/cmd-click and F12 to open what a name refers to |
| `lsp-client.js` pure, `lua-server.js` | The Lua language server (LuaLS): `lsp-client.js` speaks the protocol over any `send`/`receive`; `lua-server.js` starts it for the open game (`lsp_start` in `src-tauri/src/lsp.rs`), syncs documents and answers completion / hover / definition / diagnostics. Optional: without `third_party/luals` the editor uses `lua-intel-core.js` alone |
| `budget-core.js` pure | The Handheld panel's rows (size, art, sound, code, and the live numbers) from the console spec and measured facts; parses the game's `@@gs` stats line. The panel itself is the "Handheld" section of `main.js` |
| `help-core.js` pure, `help.js` | The Help window: reads `docs/help/*.html` (comment header + HTML), search, contents, a Lua colourer, the API page made from `engine/api/gs.d.lua`, and the files of a tutorial's game (`gameFiles`). `help.js` is the dialog: "Copy", "Add to my game" and "Make this game" |
| `consoles.js` pure, `console-editor.js`, `console-check.js` pure | Console specs: defaults/validation, the dialog, project-vs-console budget checks |
| `sprite-editor.js`, `sprite-core.js` pure, `sprite-io.js`, `palette-ui.js` | Pixel editor for sprites and tilesets (`History` undo class lives in `sprite-core.js`); the Select tool (`sel` floats lifted or pasted pixels until `settle`; `boxBetween`, `liftArea`, `stampArea`, `flipArea` in sprite-core; one clipboard shared by every editor); with colour banks, a sprite's bank picker and a tileset's bank ticks |
| `palette-core.js` pure, `palette-editor.js` | Colour banks (`palette.json`, GBA style): 15-bit colours, checks, per-tile bank checks and snapping, place-for-place recolouring, the starter banks; the Colours editor (side tree item under game.lua) |
| `info-core.js` pure | Game info (`meta/info.json`: title, description, developer, genre, players; pictures `PICTURES`: box art, screenshot, logo in `meta/`): normalising, PNG and BMP reading (the screenshot comes from `take_screenshot`), the `gamelist.xml` `<game>` entry that `scripts/gamelist.mjs` prints for `scripts/push.sh`. The dialog is the "game info" section of `main.js` |
| `room-core.js` pure, `room-editor.js` | Scene layouts (`scenes/<name>.layout.lua`) and rooms (`rooms/<name>.lua`), the same data: `parseRoom` reads the data subset of Lua (refuses code, so such a file opens as text), `serializeRoom` writes it back tidy (a tile row per line, an entity, text or picture per line, `paths`, `code`); entities are `[kind, x, y, props?, name?]`, texts and pictures objects; `layoutNames`, `nameProblem`, `textBox`. The layout editor (tools and the view controls in a row over the canvas; the left column has two tabs, everything in the layout by kind and the layout's details (size: one screen or bigger, background from the palette, the code it runs, edit as text); the right column is the tool's panel, for Select the selected thing: a searchable Add list of entities and sprites, panel styles = the tileset's 3x3 blocks that start every third tile; built-in fonts drawn with `fonts.js`, the runtime's own letters and shadows (`builtinWidth`, `glyphOf`, `shadowOf` in room-core); new texts are round_tall with a shadow; `self.` labels for the selected thing, the one under the pointer and the current tool's kind; only the Select tool selects, hovers, moves and resizes, the other tools only place) paints tile layers, places entities, texts and pictures (also dragged in from the palettes or the side tree: `PLACE` data), names them (shown as `self.<name>`), draws paths, sets the size and which scene's code a layout runs. It remembers renames until save (`getRenames`); `main.js` (`carryRenames`) then rewrites `self.old` in the code (`renameSceneFields` in rename-core.js) and in other layouts running the same code. Scenes open from the Scenes group (`openScene`: the half last open, else the layout when there is one); a scene is one tab (`scene:<name>`) with Layout and Code inside it (`sceneParts`, `openScenePart` makes a missing half); rooms (the older home of levels, only shown when a game has some, no + any more) open from Rooms (`openRoom`), and `roomToLayout` in `main.js` moves one to `scenes/` (its `gs.load_room` calls become `gs.load_layout`, `roomCallsToLayout` in rename-core) |
| `search-core.js` pure | Find and replace across the game's Lua files, `outline` (functions in a file), `tidyLua` (the Tidy button: `reindent`, then `wrapComments` to `COMMENT_WIDTH` = 100; indentation from blocks and brackets; a test runs it over every Lua file in the repo and the tutorials, which must come out unchanged; the engine's files only have to pass `reindent`), `applyEdits` (language-server edits) |
| `music-core.js` pure | Reading a song with music theory: `findKey` (Krumhansl-Kessler), `nameChord`, `songNotes`, `analyzeSong` (key and notes outside it, chords by bar, melody on the chords at strong beats, semitone clashes, shrill/muddy registers, leaps, span, repetition, density) and `describeAnalysis` (short text). Used by the MCP server's `song_check`; the studio does not show it yet |
| `inspector-core.js` pure | The Inspector tab: `@@gsi` lines in, the GS_INSPECT command text out, kinds sorted by cost. The tab itself is the "inspector" section of `main.js` |
| `theme.js` | The look: follows the system's light or dark mode live (Settings > Look can pin one), in macOS or Windows 11 colours (`style.css`, `data-os` and `data-scheme` on `<html>`, set first by a script in `index.html`). Canvas code gets colours with `color("surface")`, `ink(alpha)` (white on dark, black on light) and `tint(name, alpha)`; editors repaint through their `redraw()` when the look changes |
| `window-chrome.js` | The top bar is the title bar. macOS: `titleBarStyle Overlay` (`src-tauri/tauri.macos.conf.json`) keeps the traffic lights inside the bar, which leaves 92 px for them; in fullscreen macOS shows them in its own strip, so the bar drops that room. Windows: no system title bar (`tauri.windows.conf.json`), so the bar draws Windows 11 caption buttons. Empty parts of the bar get `data-tauri-drag-region`. In a browser, `?chrome=mac` or `?chrome=windows` shows either bar |
| `panels.js` | Drag the lines between the side bar, the editor, the output and the split view to resize them (CSS variables `--side-w`, `--log-h`, `--split-w`; double-click for the usual size; remembered in localStorage) |
| `play-core.js` pure, `play-panel.js` | The Play panel (the game inside the studio): `decodeFrame` reads the runtime's frame messages (`GS_EMBED`, runtime/main.c "embedded preview"), `KEYS` / `keyBit` are the runtime's keyboard keys as a button mask, `fitScale`; the panel draws frames on a canvas and sends the keys held while it has focus (`preview_buttons`). Run in `main.js` passes a `Channel` to `run_preview`; Settings > Run games picks the panel or a window (localStorage `gs.runIn`) |
| `steps-core.js` pure | The First steps checklist on the welcome screen (kept in localStorage) |
| `rename-core.js` pure | `roomCallsToLayout` (a room moved to scenes/). Rename a resource and rewrite the sound files that name it; counts mentions in Lua code; `renameInCode` rewrites the plain ways Lua names a moved or renamed code file (module strings, `gs.spawn` / `gs.goto_scene` / `gs.load_room`, room entity lists) or asset (`sprite =`, `set_sprite`, `tileset =`, `gs.sfx`, `gs.music`, ...; layouts and rooms are rewritten as data) |
| `wav.js` pure | WAV import checks |
| `style.css` (~480) | All styles; sections per editor. Colours are CSS variables on `:root` |

Imports: `main.js` imports everything; editors import `audio-core.js` / `sprite-core.js` (History) / `instrument-panel.js` / `lanes.js`. `engine/instruments.json` is imported
by `main.js` only (`audio-core.js` receives the instruments through `setBuiltinInstruments`, so tests can load it without JSON imports).
