# studio/src-tauri/: the Rust back end

Two files matter: `src/lib.rs` (~700 lines) and `src/lsp.rs` (the Lua language server helper process); `main.rs` just calls `run()`. Config: `tauri.conf.json`, `capabilities/default.json`. `target/` and `gen/` are build output. `cargo check` here after edits.

**Tools folder ("workspace" in the code):** the folder that holds `build/gs`, `build-aarch64/gs`, `consoles/`, `assets/` and the examples in `carts/`. Default is the repo root (two levels above this crate); changeable in Settings.
**Games are folders anywhere.** The `cart` every command takes is either the absolute path of a game folder the person picked (`open_folder`, `new_project`, `copy_example`: the native folder dialog runs in Rust through `tauri-plugin-dialog`, so the page never invents a path) or, for the examples and tests, a plain name in `<workspace>/carts/`. `cart_dir` accepts a path only if it is in the recent-projects list (`projects.json` beside `settings.json` in the app's config folder; `list_projects`, `forget_project`). `cart_label` is the folder's name, used for packed cartridges. What the studio remembers about a game (open tabs, the tab you were on) is `<game>/.gamestudio/state.json` (`read_project_state`, `write_project_state`); `safe_rel` refuses dot folders, so these two commands are the only way in, and the runtime never packs dot files. `reveal_project` opens the folder in Finder/Explorer.

Commands (all `#[tauri::command]`, registered in `generate_handler!` near the bottom; each has a twin in `../src/mock-backend.js`):
settings (`get_settings`, `save_settings`, `runtime_status`) · projects (`list_projects`, `forget_project`, `open_folder`, `new_project`, `list_examples`, `copy_example`, `read_project_state`, `write_project_state`, `reveal_project`) · consoles (`list_consoles`, `save_console`, `delete_console`) · games (`list_carts`, `list_games`, `list_files`, `new_cart`, `new_file`, `cart_size`)
· files (`read_file`, `write_file`, `read_binary`, `write_binary`, `rename_file`, `delete_file`) · run (`run_preview(cart, embed, on_frame)` (starts the game with `GS_DEV=1`, so live reload is on; with `embed` = the console's screen it has no window and its frames come through the `on_frame` Channel, see `relay_frames`), `preview_buttons(mask)` (the keys held in the Play panel), `stop_preview`, emits `log` and `preview-state` events)
· Lua language server (`lsp_start(cart)` returns the game's absolute folder, `lsp_send(message)` writes one JSON message, `lsp_stop`; every server message comes back as an `lsp-message` event; the process is killed when the app exits; see `../src/lua-server.js`) · audio (`render_audio(desc, cart)` runs `build/gs render-audio` with the cart as working directory so `sounds/...` samples resolve) · `pack_cart` · `list_devices(adb_path)` (shared `scripts/adb.mjs` discovery) · `push_cart` (always runs `scripts/push.sh` over ADB with a device profile made from Settings: runtime, core, cart, launcher, game list entry and box art; no checkout profile fallback). Old SSH Settings require review and Save; their fields are never returned or copied to the device profile. Node.js is external, with common GUI-app PATH locations added; ADB is external too, discovered by the shared helper in PATH, Homebrew or standard Android SDK folders, or an explicit Settings path.

Rules: every path from the front end goes through `valid_name` / `safe_rel` (no `..`, no absolute paths, restricted characters). Anything that spawns a process pipes stdout/stderr as `log` events
(`run_logged`). `new_cart` only makes the folder: the starter files come from `src/project-core.js` (`newGameFiles`). The project is its folder (no index file), so a new resource group
is a `GROUPS` entry there, not a Rust change.
