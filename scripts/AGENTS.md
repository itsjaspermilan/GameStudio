# scripts/: builds and the device

| Script | What |
| --- | --- |
| `build.sh` | Desktop build: `cmake -S . -B build && cmake --build build` → `build/gs` (needs `brew install cmake pkgconf`) |
| `build-aarch64.sh` | Device build with `zig cc` (pinned zig 0.15.2 in `.tool-versions`) linked against the handheld's own `libSDL2-2.0.so.0` (`GS_SYSTEM_SDL2`); downloads a checksum-verified Debian sysroot on first use (`fetch-sysroot.sh`) into `third_party/sysroot-aarch64/` (gitignored). Targets glibc 2.31 (change in `zig-cc-aarch64`) |
| `toolchain-aarch64.cmake`, `zig-cc-aarch64`, `zig-ar`, `zig-ranlib` | The cross toolchain wrappers; rarely touched |
| `push.sh <cart-dir>` | `DEVICE_ENV=<file>` reads that device file instead of `scripts/device*.env`, `GS_BUILD_DIR=<folder>` makes the packed game and launcher there instead of `build/` (both used by the studio app). Packs a cart (`build/gs pack`), copies `build-aarch64/gs`, the General MIDI SoundFont (once), and the cart to the device over ssh/scp. With `DEVICE_PORTS_DIR` it also writes a launcher. With `DEVICE_ROMS_DIR` as well, a cart whose `meta/info.json` names a console (`"console": "dot"`) gets `<roms>/<console id>/<cart>.sh` and its console becomes its own EmulationStation system (Glow43, Glow169, ... defined in `/userdata/system/configs/emulationstation/es_systems_gamestudio.cfg`, same `sh` launcher as Ports; EmulationStation reads it at start-up, so restart it after the first push of a new console). Carts without one, and everything when `DEVICE_ROMS_DIR` is unset, go to Ports as `GS-<cart>.sh`. `GS_DEBUG=1` makes test launchers log input and exit after `GS_DEBUG_SECONDS`. Every launcher it writes keeps its shell alive (no `exec`) and restores the CPU's lowest clock when the game ends, because the runtime raises it while frames are late (`runtime/AGENTS.md`) |
| `GS_DEVICE=muos push.sh <cart-dir>` | Uses `scripts/device-muos.env` (template `device-muos.env.example`; `DEVICE_OS=muos`) instead of `device.env`: muOS (MustardOS). Copies to `/mnt/mmc/gs`, writes `ROMS/<console name>/<cart>.sh` (carts without a console go to `ROMS/Tools`), assigns that folder to muOS's External - Ports system in `/opt/muos/share/info/assign/assign.json` (key: the folder name in lower case without spaces), sets the game's title in `MUOS/info/name/global.json` and its box art, screenshot and description in `MUOS/info/catalogue/External - Ports/`. muOS's hostname does not resolve on most networks: use its IP |
| `GS_DEVICE=<name> push.sh <cart-dir>` with `DEVICE_OS=nextui` | NextUI on the TrimUI Brick (template `device-nextui.env.example`, one `device-<name>.env` per Brick; SSH from the Pak Store's Native SSH, which needs TrimUI firmware 1.1+). A cart with a console is copied as a "rom" to `Roms/<console name> (<TAG>)/<cart>.<cart_extension>` (`breakout.g43`; an older `<cart>.cart` there is removed) (Glow43 is `G43`, Glow169 `G169`, a custom console its id in capitals), run by one launcher per console, `Emus/tg5040/<TAG>.pak/launch.sh`: NextUI's emulator `minarch.elf` with the gs libretro core (`build-aarch64/gs_libretro.so`, copied beside the SoundFont), so the console has NextUI's menu, button settings, sleep, save states and Resume. `GS_NEXTUI_PROGRAM=1` writes the old launcher that runs `gs` itself instead. `GS_DEBUG`/`GS_PERF` pushes change the launcher for every game of that console. Title in the folder's `map.txt`, box art in `.media/<cart>.png`, the console logo in `Roms/.media/`. Saves go to `Saves/<TAG>/<cart>`. Carts with no console become `Tools/tg5040/<title>.pak`. gs, the SoundFont and pad map live in `DEVICE_DIR` (`/mnt/SDCARD/GameStudio`). The device has no python3; NextUI's SDL2 (2.30, `mali` driver) is in `/usr/trimui/lib` |
| `build-app.sh` | Builds `GameStudio.app` for this Mac with everything inside it (unsigned, this Mac only): builds both runtimes, copies what the app uses into `studio/src-tauri/bundled/gamestudio/` (gitignored: the runtimes and core, the SoundFont, console specs and logos, `engine/api`, `push.sh`, the examples as git has them) and runs `tauri build` with `studio/src-tauri/tauri.bundle.json`, which adds that copy to the app's resources. The app uses the copy as its workspace; what it writes goes to its own folders (see `studio/AGENTS.md`) |
| `setup-key.sh <user>@<host>` | Lets the studio and `push.sh` log in without a password: makes GameStudio's own key `~/.ssh/gamestudio_ed25519` if there is none (other keys untouched) and puts it in the handheld's `~/.ssh/authorized_keys` over ssh (asks the handheld's password once, in the terminal; not `ssh-copy-id`, which writes the Dropbear file on the Brick because its firmware is OpenWrt, while it runs OpenSSH). On NextUI it lands in `/root/.ssh/authorized_keys` on the Brick's internal overlay, so it survives restarts until a firmware update. `push.sh` uses the key when it exists, opens its shared connection by itself (`ControlMaster=auto`), and exits with code 3 when it reaches the handheld but cannot log in; the studio then shows a dialog with **Set up in Terminal** (`setup_device_key` in `lib.rs` opens Terminal on this script). Settings has the same button |
| `run.sh <cart-dir>` | `push.sh`, then launches over ssh (optionally stopping the device's frontend first) |
| `fetch-luals.sh` | Downloads the Lua language server into `third_party/luals` for this Mac (pinned version, checked against a SHA-256). The studio runs without it |
| `summarize-perf.mjs` | Turns a `GS_PERF` log into one row per scenario (a game marks scenarios with `gs.mark(text)`). |
| `make-console-art.mjs`, `knulli-theme.sh` | Writes `assets/console-art/<id>.png` (the carousel panel of a console); `knulli-theme.sh on|off` switches the Knulli theme's logos and artwork between its own and ours (restart EmulationStation afterwards) |
| `make-console-logos.mjs`, `make-cart-art.mjs` | Writes `assets/console-logos/glow43` and `glow169` (`.svg` and `.png`: "GLOW" and the number with a pixel glow; preview PNG optional); renders a game's screenshot (640x480, the handheld's size), logo and a plain box art into its `meta/` from the game itself (reads `meta/info.json`; `--sprites a,b,c` picks the cover sprites, shown side by side) |
| `lib/cover.mjs` | A 240x300 cover drawn by the runtime at 120x150 with the game's own sprites (a band naming the console, the title along the bottom) and doubled: muOS draws box art at its own size over the right of its full-width game list, so a bigger cover hides the names. `make-cart-art.mjs` uses it |
| `make-app-icons.mjs` | Writes the studio's app icons into `studio/src-tauri/icons/`: a d-pad as pixel art (a raised plus with arrows), on Apple's tile for `icon.icns` and alone for `icon.ico` and the PNGs Tauri lists. Drawn on 32 and 16 px grids in the script and only scaled by whole numbers; SVGs of the drawings land in `icons/source/`. Packs the `.icns` with `iconutil` on a Mac. Run from the repo root |
| `make-fonts.mjs` | Writes `runtime/fonts.h` and `studio/src/fonts.js` from the letters drawn in `engine/fonts/round-*.txt` and `square-*.txt` (both by hand), and makes the bold style from round (strokes thickened, one-pixel gaps widened first). Run it after editing the letters, then `build.sh` (`studio/test/fonts.test.mjs` checks both files are up to date and that the studio measures text as the runtime does) |
| `make-buttons.mjs` | Draws the button icons texts show for `{a}`, `{start}` ... (face, shoulder, pill and d-pad shapes with their letters, small and tall) and the styles that colour them (gba, snes, nes, mono); writes `engine/gs/buttons_art.lua` and `studio/src/buttons.js`. Run it after changing an icon or a style, then `build.sh` (`studio/test/buttons.test.mjs` checks both files are up to date) |
| `device.env.example` → `device.env` | Host, user, folders for the device. `device.env` is gitignored; never print or commit it |

The studio's "Send to device" always runs `push.sh` (`push_cart` in `studio/src-tauri/src/lib.rs`), so there is one place to change: it writes a NextUI device file from its Settings (host, user, folder `/mnt/SDCARD/GameStudio` by default, the shared SSH connection `~/.ssh/gamestudio-<user>@<host>`) into its scratch folder, and uses `scripts/device.env` from the workspace only when Settings has no address. `push.sh` rebuilds both runtimes in a checkout (incremental, about a second); an installed app uses its prebuilt pair. `gamelist.mjs` prints a cart's game list entry; push.sh needs `node` and, on the device, `python3` (Knulli has it) to merge it.
The device runtime is **unverified on real hardware** for video (KMSDRM), controller mapping and launching while the frontend owns the display: say so when reporting, never claim it was tested on the device.

- `lib/` holds the shared generators: `lib/canvas.mjs` (an indexed-colour pixel canvas: shapes, spheres, outlines, mirroring; draw every sprite at its real size, enlarging a smaller design looked blotchy), `lib/music.mjs` (sound effects from step lists; `Song`, songs from a chord plan, a seeded melody, harmony/bass/drum styles and a per-song `level`; `jingle`), `lib/preview.mjs` (contact sheets: `node scripts/lib/preview.mjs out.png <art module>.mjs EXPORT 6 4`). The MCP server (`tools/mcp/`) uses them too.
- The art tools render through `picture-cart.mjs` (a throwaway framework game that draws one picture). The generators that made the old sample games (Void Swarm, Panel Pop) are in git history before they were removed.
