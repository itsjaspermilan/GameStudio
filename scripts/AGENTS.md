# scripts/: builds and the device

| Script | What |
| --- | --- |
| `build.sh` | Desktop build: `cmake -S . -B build && cmake --build build` → `build/gs` (needs `brew install cmake pkgconf`) |
| `build-aarch64.sh` | Device build with `zig cc` (pinned zig 0.15.2 in `.tool-versions`) linked against the handheld's own `libSDL2-2.0.so.0` (`GS_SYSTEM_SDL2`); downloads a checksum-verified Debian sysroot on first use (`fetch-sysroot.sh`) into `third_party/sysroot-aarch64/` (gitignored). Targets glibc 2.31 (change in `zig-cc-aarch64`) |
| `toolchain-aarch64.cmake`, `zig-cc-aarch64`, `zig-ar`, `zig-ranlib` | The cross toolchain wrappers; rarely touched |
| `push.sh <cart-dir>` | `DEVICE_ENV=<file>` reads that device file instead of `scripts/device*.env`, `GS_BUILD_DIR=<folder>` makes the packed game and launcher there instead of `build/` (both used by the studio app). Packs a cart (`build/gs pack`), copies `build-aarch64/gs`, the core and the cart over ADB with hash-checked atomic file replacement; the cart carries its SoundFont. With `DEVICE_PORTS_DIR` it also writes a launcher. With `DEVICE_ROMS_DIR` as well, a cart whose `meta/info.json` names a console gets `<roms>/<console id>/<cart>.sh` and its console becomes its own EmulationStation system (Glow43, Glow169, ... defined in `/userdata/system/configs/emulationstation/es_systems_gamestudio.cfg`, same `sh` launcher as Ports; EmulationStation reads it at start-up, so restart it after the first push of a new console). Carts without one, and everything when `DEVICE_ROMS_DIR` is unset, go to Ports as `GS-<cart>.sh`. `GS_DEBUG=1` makes test launchers log input and exit after `GS_DEBUG_SECONDS`. Every launcher it writes keeps its shell alive (no `exec`) and restores the CPU's lowest clock when the game ends, because the runtime raises it while frames are late (`runtime/AGENTS.md`) |
| `GS_DEVICE=muos push.sh <cart-dir>` | Uses `scripts/device-muos.env` (template `device-muos.env.example`; `DEVICE_OS=muos`) instead of `device.env`: muOS (MustardOS). Copies to `/mnt/mmc/gs`, writes `ROMS/<console name>/<cart>.sh` (carts without a console go to `ROMS/Tools`), assigns that folder to muOS's External - Ports system in `/opt/muos/share/info/assign/assign.json` (key: the folder name in lower case without spaces), sets the game's title in `MUOS/info/name/global.json` and its box art, screenshot and description in `MUOS/info/catalogue/External - Ports/`. Requires firmware with USB ADB enabled |
| `GS_DEVICE=<name> push.sh <cart-dir>` with `DEVICE_OS=nextui` | NextUI (template `device-nextui.env.example`, one `device-<name>.env` per handheld with ADB enabled). A cart with a console is copied as a "rom" to `Roms/<console name> (<TAG>)/<cart>.<cart_extension>` (`breakout.g43`; an older `<cart>.cart` there is removed) (Glow43 is `G43`, Glow169 `G169`, a custom console its id in capitals), run by one launcher per console, `Emus/<DEVICE_PLATFORM>/<TAG>.pak/launch.sh`: NextUI's emulator `minarch.elf` with the gs libretro core (`build-aarch64/gs_libretro.so`), so the console has NextUI's menu, button settings, sleep, save states and Resume. `GS_NEXTUI_PROGRAM=1` writes the old launcher that runs `gs` itself instead. `GS_DEBUG`/`GS_PERF` pushes change the launcher for every game of that console. Title in the folder's `map.txt`, box art in `.media/<cart>.png`, the console logo in `Roms/.media/`. Saves go to `Saves/<TAG>/<cart>`. Carts with no console become `Tools/<DEVICE_PLATFORM>/<title>.pak`. gs and pad map live in `DEVICE_DIR` (`/mnt/SDCARD/GameStudio`); `DEVICE_SDCARD` defaults to `/mnt/SDCARD`, `DEVICE_PLATFORM` to `tg5040`. Verify those defaults for each model. The device has no python3; NextUI's SDL2 (2.30, `mali` driver) is in `/usr/trimui/lib` |
| `build-app.sh` | Builds `GameStudio.app` for this Mac with everything inside it (unsigned, this Mac only): builds both runtimes, copies what the app uses into `studio/src-tauri/bundled/gamestudio/` (gitignored: the runtimes and core, the SoundFont, console specs and logos, `engine/api`, `push.sh`, the examples as git has them) and runs `tauri build` with `studio/src-tauri/tauri.bundle.json`, which adds that copy to the app's resources. The app uses the copy as its workspace; what it writes goes to its own folders (see `studio/AGENTS.md`) |
| `adb.mjs`, `device.sh` | Shared ADB program discovery, device enumeration/selection, legacy-shell exit status handling and SHA-256-verified staged transfers. External Platform-Tools: PATH, Homebrew, standard Android SDK folders, or `ADB=/full/path/to/adb`. `DEVICE_SERIAL` (override `GS_ADB_SERIAL`) is required with several devices; never silently falls back from an absent/offline/unauthorized selection. Old SSH profile fields are rejected, not migrated. `studio/test/adb.test.mjs` mocks ADB; never test transfers against real games |
| `run.sh <cart-dir>` | `push.sh`, then launches the deployed cart with the standalone runtime over ADB on the same selected serial (optionally stopping the frontend first); use the device menu for its libretro launcher |
| `fetch-luals.sh` | Downloads the Lua language server into `third_party/luals` for this Mac (pinned version, checked against a SHA-256). The studio runs without it |
| `summarize-perf.mjs` | Turns a `GS_PERF` log into one row per scenario (a game marks scenarios with `gs.mark(text)`). |
| `make-console-art.mjs`, `knulli-theme.sh` | Writes `assets/console-art/<id>.png` (the carousel panel of a console); `knulli-theme.sh on|off` switches the Knulli theme's logos and artwork between its own and ours (restart EmulationStation afterwards) |
| `make-console-logos.mjs`, `make-cart-art.mjs` | Writes `assets/console-logos/glow43` and `glow169` (`.svg` and `.png`: "GLOW" and the number with a pixel glow; preview PNG optional); renders a game's screenshot (640x480, the handheld's size), logo and a plain box art into its `meta/` from the game itself (reads `meta/info.json`; `--sprites a,b,c` picks the cover sprites, shown side by side) |
| `lib/cover.mjs` | A 240x300 cover drawn by the runtime at 120x150 with the game's own sprites (a band naming the console, the title along the bottom) and doubled: muOS draws box art at its own size over the right of its full-width game list, so a bigger cover hides the names. `make-cart-art.mjs` uses it |
| `make-app-icons.mjs` | Writes the studio's app icons into `studio/src-tauri/icons/`: a d-pad as pixel art (a raised plus with arrows), on Apple's tile for `icon.icns` and alone for `icon.ico` and the PNGs Tauri lists. Drawn on 32 and 16 px grids in the script and only scaled by whole numbers; SVGs of the drawings land in `icons/source/`. Packs the `.icns` with `iconutil` on a Mac. Run from the repo root |
| `make-fonts.mjs` | Writes `runtime/fonts.h` and `studio/src/fonts.js` from the drawings in `engine/fonts/`, making bold from round and preserving the coverage in the smooth sans/serif/mono fonts. Run it after editing the letters, then `build.sh` (`studio/test/fonts.test.mjs` checks generated files, metrics and rendered pixels). `rasterize-fonts.py` optionally rebuilds the smooth drawings and OFL notices from pinned Google Fonts sources (Python 3 + Pillow 11.3.0); normal builds need neither Pillow nor downloads |
| `make-buttons.mjs` | Draws the button icons texts show for `{a}`, `{start}` ... (face, shoulder, pill and d-pad shapes with their letters, small and tall) and the styles that colour them (gba, snes, nes, mono); writes `engine/gs/buttons_art.lua` and `studio/src/buttons.js`. Run it after changing an icon or a style, then `build.sh` (`studio/test/buttons.test.mjs` checks both files are up to date) |
| `device.env.example` → `device.env` | ADB serial, firmware and folders for the device. `device.env` is gitignored; never print or commit it |

The studio's "Send to device" always runs `push.sh` (`push_cart` in `studio/src-tauri/src/lib.rs`): it writes an ADB profile from Settings into its scratch folder and never falls back to the checkout's profile. Settings select NextUI (default), Knulli or muOS, an ADB serial and optional program/folder overrides. Legacy SSH settings require review and Save. `push.sh` rebuilds both runtimes incrementally in a source checkout; the packaged app uses its bundled binaries without trying to build in read-only resources. `gamelist.mjs` uses `studio/src/info-core.js` (also bundled) to print the game list entry; push.sh needs `node` (bundled with the app) and, on Knulli, `python3` to merge it. Transfers are atomic per file, not across the whole deployment; cancelled sends can leave uniquely named stage files but never partially overwrite the live destination.
The device runtime is **unverified on real hardware** for video (KMSDRM), controller mapping and launching while the frontend owns the display: say so when reporting, never claim it was tested on the device.

Knulli's shell launcher supplies `SDL_GAMECONTROLLERCONFIG`, not RetroArch controller bindings. The per-game RetroArch config selects the
SDL2 joypad driver and its standard button IDs, so controls also work on fresh installs without `retroarchcustom.cfg` or autoconfig profiles.

- `lib/` holds the shared generators: `lib/canvas.mjs` (an indexed-colour pixel canvas: shapes, spheres, outlines, mirroring; draw every sprite at its real size, enlarging a smaller design looked blotchy), `lib/music.mjs` (sound effects from step lists; `Song`, songs from a chord plan, a seeded melody, harmony/bass/drum styles and a per-song `level`; `jingle`), `lib/preview.mjs` (contact sheets: `node scripts/lib/preview.mjs out.png <art module>.mjs EXPORT 6 4`). The MCP server (`tools/mcp/`) uses them too.
- The art tools render through `picture-cart.mjs` (a throwaway framework game that draws one picture). The generators that made the old sample games (Void Swarm, Panel Pop) are in git history before they were removed.
