# scripts/: builds and the device

| Script | What |
| --- | --- |
| `build.sh` | Desktop build: `cmake -S . -B build && cmake --build build` → `build/gs` (needs `brew install cmake pkgconf`) |
| `build-aarch64.sh` | Device build with `zig cc` (pinned zig 0.15.2 in `.tool-versions`) and SDL3 linked statically; downloads a checksum-verified Debian sysroot on first use (`fetch-sysroot.sh`) into `third_party/sysroot-aarch64/` (gitignored). Targets glibc 2.31 (change in `zig-cc-aarch64`) |
| `toolchain-aarch64.cmake`, `zig-cc-aarch64`, `zig-ar`, `zig-ranlib` | The cross toolchain wrappers; rarely touched |
| `push.sh <cart-dir>` | Packs a cart (`build/gs pack`), copies `build-aarch64/gs`, the General MIDI SoundFont (once), and the cart to the device over ssh/scp. With `DEVICE_PORTS_DIR` it also writes a launcher. With `DEVICE_ROMS_DIR` as well, a cart whose `meta/info.json` names a console (`"console": "dot"`) gets `<roms>/<console id>/<cart>.sh` and its console becomes its own EmulationStation system (Dot, Dash, ... defined in `/userdata/system/configs/emulationstation/es_systems_gamestudio.cfg`, same `sh` launcher as Ports; EmulationStation reads it at start-up, so restart it after the first push of a new console). Carts without one, and everything when `DEVICE_ROMS_DIR` is unset, go to Ports as `GS-<cart>.sh`. `GS_DEBUG=1` makes test launchers log input and exit after `GS_DEBUG_SECONDS`. Every launcher it writes keeps its shell alive (no `exec`) and restores the CPU's lowest clock when the game ends, because the runtime raises it while frames are late (`runtime/AGENTS.md`) |
| `run.sh <cart-dir>` | `push.sh`, then launches over ssh (optionally stopping the device's frontend first) |
| `fetch-luals.sh` | Downloads the Lua language server into `third_party/luals` for this Mac (pinned version, checked against a SHA-256). The studio runs without it |
| `summarize-perf.mjs` | Turns a `GS_PERF` log into one row per scenario (a game marks scenarios with `gs.mark(text)`). |
| `make-console-art.mjs`, `knulli-theme.sh` | Writes `assets/console-art/<id>.png` (the carousel panel of a console); `knulli-theme.sh on|off` switches the Knulli theme's logos and artwork between its own and ours (restart EmulationStation afterwards) |
| `make-console-logos.mjs`, `make-cart-art.mjs` | Writes `assets/console-logos/dot.svg` (pixel-font logo, preview PNG optional); renders a game's screenshot, logo and box art into its `meta/` from the game itself (reads `meta/info.json`; `--sprites a,b,c` picks the cover sprites, shown side by side). Void Swarm's cover: `--sprites spr_pilot_nova,spr_e_golem,spr_pilot_mira` |
| `make-font8.mjs` | Writes `studio/src/font8.js`, the runtime's built-in 8x8 font read back from `build/gs` itself, so the layout editor draws text in the game's letters (`studio/test/font8.test.mjs` checks it still matches) |
| `device.env.example` → `device.env` | Host, user, folders for the device. `device.env` is gitignored; never print or commit it |

The studio's "Send to device" runs `push.sh` itself when `scripts/device.env` exists (`push_cart` in `studio/src-tauri/src/lib.rs`), so there is one place to change; its own plain ssh/scp path is only the fallback without `device.env` (files beside `gs`: `TimGM6mb.sf2`, `carts/`). `gamelist.mjs` prints a cart's game list entry; push.sh needs `node` and, on the device, `python3` (Knulli has it) to merge it.
The device runtime is **unverified on real hardware** for video (KMSDRM), controller mapping and launching while the frontend owns the display: say so when reporting, never claim it was tested on the device.

- `lib/` holds the shared generators: `lib/canvas.mjs` (an indexed-colour pixel canvas: shapes, spheres, outlines, mirroring; draw every sprite at its real size, enlarging a smaller design looked blotchy), `lib/music.mjs` (sound effects from step lists; `Song`, songs from a chord plan, a seeded melody, harmony/bass/drum styles and a per-song `level`; `jingle`), `lib/preview.mjs` (contact sheets: `node scripts/lib/preview.mjs out.png ../void-swarm/pilots.mjs PILOTS 6 4`). The MCP server (`tools/mcp/`) uses them too.
- `make-void-swarm.mjs` generates the art and sound of `carts/void-swarm` (sprites, backgrounds, sound effects, songs) from `scripts/void-swarm/` (`pilots/enemies/bosses/misc.mjs` art, `audio.mjs` its sound effects and the band of each song). Run it after editing any of them; it never touches the game's Lua or `meta/info.json`.
- `make-panel-pop.mjs` generates `carts/panel-pop` the same way (art in `scripts/panel-pop/art.mjs`, sound in `scripts/panel-pop/audio.mjs`, which uses `scripts/lib/music.mjs` too); it leaves the hand-written Lua and layouts (`lib/`, `scenes/`) alone and rewrites only `lib/art.lua`. `make-panel-pop-art.mjs` draws that cart's box art (run it after `make-cart-art.mjs`, which writes a generic one). Both art tools render through `picture-cart.mjs` (a throwaway framework game that draws one picture).
- `make-kitchen-rush.mjs` generates `carts/kitchen-rush` the same way (art in `scripts/kitchen-rush/art.mjs`, sound in `scripts/kitchen-rush/audio.mjs`); it rewrites only the assets and `lib/art.lua`. Its box art is the generic one from `make-cart-art.mjs carts/kitchen-rush --frames 200 --sprites spr_chef,spr_food`.
